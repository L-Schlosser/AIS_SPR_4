## 2. Motivation
 
> Why was this model selected for evaluation?
 
This model was chosen as a larger alternative to the 0.5B variant to test whether increased parameter count improves classification accuracy on the synthetic document dataset. With 1.5B parameters, it offers stronger reasoning capabilities while still being relatively lightweight compared to very large LLMs.
 
---
 
## 3. Architecture
 
### 3.1 Classification
 
The model is used as an instruction based classifier. A short prompt is generated for each document, and the model returns a predicted class name. The output is normalized through keyword matching to map variations to the canonical labels defined in the benchmark.
 
### 3.2 OCR

The model does not perform OCR. It only processes the text generated by the synthetic sample generator. Its role is limited to interpreting the extracted text and assigning it to one of the predefined document categories.

### 3.3 NET .MAUI compatibility 
The model cannot run directly inside a .NET MAUI application. Due to its size, it requires a Python backend or remote inference endpoint. The MAUI app would communicate with it via HTTP.

## 5. Strengths & Weaknesses
 
### Strengths
 
- accuracy is perfect across all document types
- classification is highly reliable even for ambiguous or similar text patterns
 
### Weaknesses
 
- latency is significantly higher than the smaller model (0.5B)
- model size makes deployment more demanding and less suitable for an app on a phone
---
 
## 6. Decision
 
**Decision:** 
The model was not selected for integration due to its latency and resource requirements.
 
**Reasoning:**
Although the accuracy is perfect and clearly superior to the smaller models, the latency of nearly two seconds per classification exceeds the acceptable threshold. The models size also makes it impractical for lightweight deployments, so it was not pursued further.
